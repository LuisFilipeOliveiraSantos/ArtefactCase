# Interaction examples

Real conversations with the agent, generated by `scripts/run_examples.py` (each file records the customer
messages, the tools the agent called with their arguments, and the replies exactly as returned).
The model used is noted at the top of each file: 01–02 ran on `gemini-3.5-flash` before its free daily quota
ran out, 03–05 on `gemini-3.5-flash-lite` (the current default).

| File | Scenario | What it demonstrates |
|---|---|---|
| [01](01-catalog-guitars-under-1000.md) | Acoustic guitars up to R$1000, then "is the cheapest nylon? does it have a pickup?" | Catalog search with category + price filter, only available items, PIX prices; follow-up resolved from context with `get_product_details`, suggests an alternative with a pickup |
| [02](02-price-promotion-and-accessories.md) | Price of the Takamine GD20, current promotions, then strings and a case | Price lookup; promotions shown as original price / discount / final price, with the no-stacking rule; accessories politely declined (manual §7.1) |
| [03](03-return-request-policy-and-order.md) | "Me arrependi da minha compra, posso devolver?" then "and if it is defective?" | **Non-trivial:** asks for identification, looks up the order, today's date and the policy, and applies the 7-day withdrawal and 30-day defect-exchange rules to the order's dates; points to the manufacturer warranty and the human team |
| [04](04-order-tracking-and-identity-check.md) | Where is order 8? (wrong e-mail first, then the right one) | Identity check before showing order data (LGPD): a wrong contact gets no data; with the right one, status, tracking code and the late delivery are reported |
| [05](05-store-info-and-off-topic.md) | Address, Saturday hours, installments, then a football question | Policy retrieval (address, hours, installment rules); off-topic question declined in the persona's tone |

## Observations (honest review)

- **03:** the defect-exchange window is counted "after receipt" while the manual says "after purchase", and the
  90-day legal warranty is not mentioned. The conclusion is still correct (both windows are closed for an
  order received in Feb/2026). A first run listed the rules without applying them to the order; the prompt
  was tightened and the example regenerated.
- **04:** the lite model first called `get_order_status` without the contact; the tool dispatcher returned an
  error (no data exposed) and the agent asked for the e-mail.
- **01–02** were generated before the final prompt changes, which touched installments and deadlines, not
  catalog behaviour.
